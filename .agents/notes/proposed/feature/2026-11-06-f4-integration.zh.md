# Agent Note: F4 可选功能整合 —— 一棵经过审计的树

Status: proposed

[English](2026-11-06-f4-integration.md) | 中文

## 问题

七个 F4 变更最初是作为七个独立分支构建的。每个属主笔记都以同一句话收尾：在编排中启用是单独的属主决策。七个绿色分支只能证明七个变更各自孤立可用，不能证明把它们一起交付的那棵树。共享辅助函数、已持久化的事件联合、工具目录豁免、TypeScript 项目引用、工作区约束与 Cordis realm，只有在七个变更全部合并时才会相遇 —— 而在那次相遇中，P6 评审发现了两个 MAJOR 缺陷以及任何单分支都无法暴露的整合发现。F4 收尾要求的产物比七个分支更强：一棵整合后的树，其门禁在固定 HEAD 上测量，并经过独立审计，然后才由人决定是否启用。

## 方案

分支 `feat/ch050-integration` 在集成时的 `origin/master` 上按依赖顺序整合七个变更 —— CH-041 最先，因为 CH-043 堆叠在它之上，然后是其余变更 —— 并在其上加带修复提交。这是启用决策将要消费的树；随附的 `sota` 笔记以可选方式增加启用，但不改变默认。七个变更按合并顺序：

- **CH-041 —— 出站提示词治理器**在组装期间限定 MCP schema 表面积（[笔记](2026-11-06-outbound-prompt-governor.zh.md)）。
- **CH-043 —— Skill 与 MCP 工具路由**在 `tool-skill` 之后加入可选的 FTS5 排序（[笔记](2026-11-06-skill-mcp-router.zh.md)）。
- **CH-042 —— 分发门禁与压力剪枝器**加入 audit/enforce 允许列表与每轮剪枝触发器（[笔记](2026-11-06-tool-dispatch-gate-and-pressure-pruner.zh.md)）。
- **CH-044 —— 被动记忆**加入有界本地存储、注入块与脱敏采集（[笔记](2026-11-06-passive-memory.zh.md)）。
- **CH-045 —— 会话交接**加入 `/handoff` 与链接子会话的检查点（[笔记](2026-11-06-session-handoff.zh.md)）。
- **CH-046 —— 遥测脱敏**通过共享规则集清洗每条出站遥测记录（[包 README](../../../../packages/session/telemetry-redaction/README.zh.md)）。
- **CH-047 —— 纵向评估**加入共享指标、使用摘要与 kill criteria（[笔记](2026-11-06-longitudinal-eval.zh.md)）。

只有两处合并冲突（CH-046 的 `tsconfig.base.json` 与 CH-047 的包 README 校验器）；两处都通过保留双方解决。树到达其集成 HEAD：37 个提交、191 个文件、+9.251/−202、工作树干净、没有 upstream，也未 push 或开 PR。这里不改变默认 preset：`standard` 仍是默认且未变，可选的 `sota` preset 仅在会话选择它时启用它们（见 [sota 笔记](2026-11-08-sota-preset.zh.md)），而宿主平面的遥测脱敏是唯一默认挂载的变更。已记录快照不变，因为没有已记录场景选择 `sota`。

## 修复

P6 评审的两个 MAJOR 发现，以及合并树暴露的整合发现，都在树内关闭并重新验证，而不是留给读者：

- **恢复后的交接投递** —— 检查点只从实时 `session/event` 状态投递，因此在新进程中被恢复的子会话永远收不到它。修复方案在宿主侧 Session 投影中折叠持久的 `handoff/checkpoint` 与已提交的投递消息；独立探针复现了：待投递日志 → 投递一次，投递提交后 → 零次，日志已记录过投递 → 零次。
- **持久注入，按持久来陈述** —— 记忆块与检查点由 agent loop 追加到会话表面，因此它们是后续请求会重发的持久历史。README、类型注解与属主笔记现在都这样陈述并写明成本；易变消息来源仍使用已持久化的 `plugin` 变体，因此没有改变来源联合。
- **持久化兼容性** —— 三个可选事件不是可忽略的，早于本构建的读取器会拒绝包含它们的日志。[持久化记录](../../../../docs/persistence-changes/2026-11-06-opt-in-session-events.zh.md)现在只声明代码实际做到的事：same-version 仅指没有结构变更，不包含前向兼容。只要可选功能未挂载，就不存在受影响的会话。
- **整合发现** —— 新基线里的 typert schema 物化、`tool-dispatch-gate` 的工具目录豁免、`skillRouter` 的 realm 放置与目录角色、新包的工作区约束、持久化记录、去重整改（共享文本边界与命令生命周期）以及 lint/弃用清理，都已进入树内并重新测量。
- **已声明的例外** —— `tool-skill` 保留两处已弃用的同步历史读取，收在一个共享辅助函数后面，并登记在 CH-041 与 CH-043 笔记中，迁移被延后；MINOR-3 是审计中唯一未关闭的 minor，且它是已声明的，不是隐默的。

## 审计与门禁

对整合树的独立审计（属主案卷中的 `10-AUDITORIA-CH050`）重新测量了最终 HEAD，记录 0 个 BLOCKER、0 个 CRITICAL、0 个 MAJOR，MINOR-3 已声明，INFO 项作为债务。集成 HEAD 处的门禁：

| 门禁 | 命令 | 结果 |
|---|---|---|
| 静态检查 | `pnpm run check:ci:static` | 55/55 |
| 文档 | `pnpm run test:docs` | 20/20 |
| 包不变量 | `pnpm run verify-package-invariants` | 39/39 |
| Typecheck | `pnpm run typecheck` | exit 0 |
| Lint | `pnpm run lint:contracts-ready` | 0 warnings, 0 errors |
| 重复检测 | `pnpm run duplication` | 0 clones |
| 聚焦测试 | `pnpm exec vitest run <17 paths>` | 623/623 |

聚焦测试计数是 F4 与受影响包的集合，不是整个仓库测试套件；审计还为去重提交运行了 `llm`（1.234）与 `session`+`agent-loop`（923）套件。

## 已考虑的替代方案

- **每个变更作为自己的 PR 合入 master，之后再启用** —— 拒绝：这把跨变更的失败推到发布时，也没有评审者看到组合后的行为；这棵树正是共享辅助函数、事件联合、realm 与目录交互被测量的地方。
- **把七个变更压成一个提交** —— 拒绝：这会抹掉哪个变更拥有哪个缺陷，也让单独回退某个可选功能变得不可能；合并提交是整合的证据。
- **在这里把可选功能启用到默认 `standard` 预设** —— 拒绝：整合不是启用；默认 agent 的模型可见输入与快照在本分支中不得改变，产品决策是 [`sota` 预设](2026-11-08-sota-preset.zh.md)。
- **只凭 P6 证据封存** —— 拒绝：P6 评审的是各分支，其「表面干净」的声明不可复现，且它的 MAJOR-1 只在合并树里出现；封存需要一个独立的 HEAD。
- **保持分支本地并推迟门禁** —— 拒绝：上表中的每道门禁都在最终 HEAD 上重新测量过。37 个提交仍在本地，因此 CI 尚未看到合并结果。

## 验收标准

- 七个变更存在于集成基线上，按依赖顺序，连同集成 HEAD 与干净工作树。
- 上表中的每道门禁在该 HEAD 上为绿；审计报告 0 个 BLOCKER/CRITICAL/MAJOR，MINOR-3 已声明，INFO 项作为债务记录。
- P6 的 MAJOR-1 与 MAJOR-2 通过恢复测试/探针与修正后的文档完成修复；持久化记录陈述真实的（不）兼容性。
- 没有任何已发布预设或编排挂载七个中的任何一个；已记录快照不变。
- 分支没有 upstream，也不自带 PR；push 它以及启用任何可选功能仍是属主决策。

## 风险

- **模拟价值** —— 每次请求 1.393 tokens（0,45 %）与剪枝器的 12,94 %/20,54 % 是对仓库外日志的重放模拟；审计将其标记为未经独立执行验证（INFO-2）。树证明机制，不证明收益；实跑评估仍是启用门槛。
- **前向兼容** —— 早于本构建的读取器会拒绝在某个可选功能挂载期间写入的任何会话，因为三个事件不是可忽略的。不挂载让风险保持潜伏；启用则为降级的用户创造该风险。
- **延后的弃用读取** —— `tool-skill` 的例外是同步读取 API 的唯一迁移点；在未迁移该辅助函数的情况下移除该 API，目录与请求排序都会失效。
- **仅本地的分支** —— 37 个提交与 191 个文件只存在于一台机器上；CI 与评审只有在 push 之后才会看到合并结果。
- **封存不等于价值** —— 审计封存的是树，不是产品；CH-047 的 30 天窗口与其 kill criteria 仍然待定，且仍可能返回「disable」。

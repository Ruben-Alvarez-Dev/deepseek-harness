# Agent Note: 带有限索引与脱敏捕获的本地被动记忆

Status: proposed

[English](2026-11-06-passive-memory.md) | 中文

## 问题

会话启动时没有持久背景：操作者在早期工作中积累的知识，只有在 agent 决定调用记忆工具时才可用，而工具调用会消耗一个步骤、一个 schema，以及模型可能跳过的一次决策。计划的记忆方向（P4）希望被动注入——记忆因任务匹配而随请求到达，而不是因为 agent 主动索取。远程后端不在本变更范围内，且带有最糟糕的失败模式：私有会话文本离开本机。剩下的设计空间是本地产物、确定性选择器、不会污染稳定前缀的易失注入，以及在写入前完成脱敏的捕获路径。

## 方案

`@deepseek-ai/dsh-memory-passive` 在既有 seam 上挂载三部分：

1. **有界存储（C-5）** — `memoryDir` 保存 `MEMORY.md`（规范行 `- <id> — <title> — <keywords>`，受 `maxIndexLines` 限制，默认 200）以及每个主题一个 `<id>.md`。缺少索引视为空存储；格式错误的行大声失败。
2. **易失注入器（C-3、E-2）** — 在每轮首个 `agent/pre-step`，插件对最新直接用户文本分词，对索引条目做词法排序（标题/id 命中按关键词命中的三倍计分，平局按 id），把选中条目置于不可信围栏内、受 `injectQuotaChars` 约束渲染，并作为用户消息加入该轮的 pre-step 决策；agent 循环会把它追加到会话表面，因此它成为后续请求会重发的持久历史。持久的 `memory/injected` 事件记录 id、SHA-256 摘要、字符数、配额与轮次，把块与其表面消息绑定。
3. **本地捕获（C-2）** — 会话释放时，插件取最后一段直接用户文本与助手文本，应用固定脱敏规则（私钥、`sk-` 密钥、Bearer token、JWT、GitHub token、AWS 密钥、密钥赋值），限制每侧长度，并向 `inbox.jsonl` 追加一行 JSON。该路径不发起网络或模型调用。

在合成 fixture 上测量（39 条记忆、39 条带标签任务查询）：**recall@5 1,000**，每个渲染块都低于 4000 字符配额，六条脱敏规则在密钥 fixture 上验证通过，工具运行时检查证明插件不注册任何工具。已发布预设中未挂载任何内容，因此已记录快照不变。C-4（整合调度）被有意延后：它需要 durable 调度与准入策略，本变更不拥有这些。

## 已考虑的替代方案

- **经网络的 cortex/MCP 捕获桥** — 此处拒绝：它把私有文本发送到另一个进程；后端的计划决策另行处理，先发布这一本地层是安全的。
- **把记忆注入系统提示词** — 拒绝：每次选择都会改变稳定前缀，破坏提示词缓存复用；易失尾部 token 成本更高，但前缀可复用。
- **基于嵌入的选择** — 拒绝：为排序记忆发起模型调用会给后台机制增加延迟、成本与非确定性。
- **完整转录捕获** — 拒绝：收件箱中无界私有文本；最后交互是最小有用记录，且脱敏发生在写入之前。
- **agent 可见的保存/召回工具** — 不作为主路径拒绝：那正是本方向要替代的行为；收件箱可由操作者或未来的整合步骤整理。

## 验收标准

- 在带标签 fixture 上 recall@k ≥ 0,80，k 等于注入条目数；每次注入都在配置配额内并携带不可信围栏。
- 本包注册零 tools；每轮最多注入一次；没有匹配词项时不注入。
- 捕获在脱敏后只写入本地收件箱，并记录脱敏计数；注入事件使请求可由日志加上存储重建。
- 聚焦测试、typecheck 与文档门禁通过；在编排中启用是单独的属主决策，因为它改变模型可见上下文。

## 风险

- **记忆投毒** — 注入条目是不可信文本；围栏禁止遵循其中指令，agent 必须核实主张，与会话引用完全一致。
- **词法缺口** — 同义词与改写会漏配；recall 受词表重叠与配额限制，而非语义。
- **本地捕获增长** — 收件箱没有自动整理；操作者或后续整合变更负责清理。
- **回放依赖** — 日志记录进入请求的内容，但复现文本需要记忆目录内容。
- **合成门禁** — fixture 为本包编写；recall 数字是回归信号，不是真实记忆的质量保证。

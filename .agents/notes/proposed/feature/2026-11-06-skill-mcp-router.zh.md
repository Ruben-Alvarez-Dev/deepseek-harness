# Agent Note: 零嵌入的 skill 与 MCP 工具路由器

Status: proposed

[English](2026-11-06-skill-mcp-router.md) | 中文

## 问题

随着每个 skill 与 MCP 服务器的加入，目录与可见工具集会不断增长，而当前请求只需要其中少数。目录的词法排序会保留所有 skill，只缩短描述，但它比较的是精确的小写 token，因此词形与变音符号会漏配（"outage" 匹配不到 "outages"），而且 MCP 工具元数据完全没有共享排序。嵌入式路由器会为这种必须能从会话日志回放的选择引入模型调用、延迟与非确定性。剩下的选项是一个理解词形的确定性词法索引——并且它不能隐藏任何东西，因为被隐藏的工具没有逃生口。

## 方案

`@deepseek-ai/dsh-skill-mcp-router` 在内存 SQLite FTS5（`node:sqlite`）中维护两个分区：skill 摘要（`indexSkills`）与可见 MCP 工具 schema（`indexTools`，仅 `mcp__*`），使用 `porter unicode61` 分词器。查询会被分词、去重、限量并逐个引用，然后按 `bm25` 排序。重建前先比较内容 digest，工具分区在最终 `system-prompt/assemble` 结果之后刷新，因此提示词级提供方也会被包含，而未变化集合不产生开销。服务本身不增加任何模型可见表面，也从不隐藏 skill 或工具。

集成是可选且单向的：`dsh-tool-skill` 读取 `ctx.get('skillRouter')`；存在时，top-K 完整描述集合遵循路由器的 BM25 顺序，不存在时词法回退保持不变。不新增发现工具：MCP 工具保持可见，因此 `find-mcp-tools` schema 会在每个请求上消耗提示词 token 却不增加能力；工具分区通过服务 API 留给未来的选择消费者。

在带标签的合成 fixture 上测量（32 个条目、59 条任务查询、分级相关性）：**recall@8 0,915、nDCG@8 0,932**，词法基线为 **0,890 / 0,883**；门禁目标为 0,90 / 0,80。已发布预设中未挂载任何内容，因此已记录快照不变。

## 已考虑的替代方案

- **嵌入式路由器** —— 拒绝：每次选择都产生模型调用、延迟，并且排序不确定、无法从日志回放。
- **手写 token 数组 BM25** —— 拒绝：会在已支持 FTS5 的 SQLite 之上重新实现词干化、变音折叠与排序。
- **隐藏低排名工具** —— 拒绝：可见性是工具唯一的逃生口；隐藏需要目前不存在的重新暴露机制。
- **按相关性重排所有工具** —— 拒绝：每个步骤都会改变请求头（缓存失效），且不会节省 token，因为排序不缩小集合。
- **`find-mcp-tools` 发现工具** —— 暂时拒绝：工具并未被隐藏，schema 开销买不到任何可触达能力。

## 验收标准

- 路由器在带标签 fixture 上满足 recall@8 ≥ 0,90 与 nDCG@8 ≥ 0,80，并保持领先词法基线。
- 未挂载路由器时目录与词法回退完全一致；挂载时 top-K 遵循其排序，且所有 skill 仍被列出。
- 重建确定（digest 门控）、不发起模型调用、不隐藏能力，并在运行时缺少 SQLite FTS5 时大声失败。
- 聚焦测试、typecheck 与文档门禁通过；在编排中启用是单独的属主决策，因为它会改变模型可见描述与快照。

## 风险

- **合成门禁** —— 语料与查询是为本包编写的；数字是内部回归信号，不是通用质量声明。
- **词表缺口** —— 没有共享词干的查询（"roll back" 与 "rollback"）检索不到任何内容；同义词与跨语言改写需要本变更有意避免的嵌入或翻译步骤。
- **运行时依赖** —— FTS5 需要 `node:sqlite` 支持；缺少它的运行时首次使用即大声失败，而不挂载路由器即可保留词法回退。
- **缓存归属** —— 路由器本身不改变请求；展示不同集合的消费者承担由此产生的提示词缓存影响。

# Agent Note: 出站提示词治理器 —— 有界的工具与 skill 体积

Status: proposed

[English](2026-11-06-outbound-prompt-governor.md) | 中文

## 问题

harness 每次请求都会重新发送没有上限的出站体积：skill 目录会发布每个模型可调用 skill 的（有长度上限的）描述，MCP 服务器则贡献部署方无法控制的工具 schema。SOTA 计划的 P1 假设这个体积是每次请求的主要成本，并以「tokens/请求 −20 %」作为门禁。但在三个真实会话上实测（582 次请求，见 `planificacion/20-BASELINE-CH040.md`），该体积很小：在现有 500 字符描述上限下，目录每次请求约 1.3–1.5k tokens，MCP schema 低于 3k，而总用量是每次请求 136k–405k tokens，主要由 cache read 的会话历史主导。仅靠出站体积选择无法达到 −20 % 的总量门禁；假装可以只会带来价值不可测的行为变更。

## 方案

在两个既有接缝上增加两个可独立配置、默认不启用的开关：

1. `dsh-tool-skill` 新增 `catalogTopK`（默认 `0`，即旧行为）与 `catalogSummaryDescriptionMaxLength`（默认 64）。skill 按当前直接用户消息与 skill 名称/描述的零嵌入词法重叠加权排序；前 K 个保留完整描述，其余仍以名称加一行摘要列出，`/name` 显式调用的 skill 始终保留完整描述。因为没有任何名称消失，`skill` 加载工具仍是逃生通道。
2. 新的函数插件 `dsh-system-prompt-governor` 在 `system-prompt/assemble` 瀑布事件上把 MCP 工具 schema（`mcp__<server>__<tool>`）限制在 `mcpSchemaTokenBudget`（默认 3000）。落在规范化预算前缀内的工具保留完整 schema；其后的每个 MCP 工具保留名称、`required` 列表、类型、默认值与嵌套结构，只递归移除参数中的 `description`/`examples`/`$comment`，并把工具描述截断到 `mcpToolDescriptionMaxLength`（默认 120）。切分是确定性的，非 MCP 工具不受影响；治理后的工具会进入 `request/header`，因此模型可见输入仍可从会话日志重建。该持久 header 就是决策的登记：另设每次组装的诊断事件只会为仅面向运维的可选诊断增加日志体积，因此不新增事件。

用同一固定启发式在同三个会话上实测：**每次请求约节省 1 393 tokens，占总用量的 0.45 %**（目录在 582 次请求中约 810k tokens；MCP schema 本就在预算内，为 0）。实现保持默认不启用，因为该效果不足以改变已发布快照或默认值；计划中 P1 的每请求目标应移到 P2 的结果裁剪器，那里会话历史才是主导项。

## 已考虑的替代方案

- **在 standard/cordis 预设中默认启用** —— 会为实测 <1 % 的效果改变模型可见提示与已记录快照。拒绝：可选功能不进入已发布默认值。
- **把预算硬编码在插件里** —— 违反仓库「插件不得硬编码可调项」的规则；两项都是经校验的 `Config` 字段。
- **用嵌入或外部路由器给 skill 排序** —— P1 阶段拒绝：为很小的体积在关键路径上增加模型调用或索引；FTS5 排序属于 P3。
- **全局截断所有工具 schema** —— 拒绝：非 MCP 工具是一方自有且已精简；无界部分是 MCP。
- **完全丢弃 MCP 参数结构** —— 拒绝：模型仍需能调用被治理工具；丢弃文档可恢复，丢弃可调用结构不可恢复。

## 验收标准

- `catalogTopK` 只改变渲染出的目录：每个 skill 名称仍被列出，`/name` 手势与用户可调用 skill 永不隐藏，词法无重叠时所有描述保持不变。
- 治理器对相同组装与限制具有确定性；永不修改非 MCP 工具；被治理的 MCP 工具保留名称、`required`、类型、默认值与嵌套结构。
- 聚焦测试、typecheck 与文档门禁通过；一个真实 Loader 编排测试通过 `cordis.yml` 挂载两个插件，并断言组装后的 MCP schema 被压缩。
- 在三个基线会话上的实测效果被发布，并明确记录 −20 % 总量门禁被证伪。

## 风险

- **被治理 MCP 工具的说明缺失** —— 参数文档不再到达模型；调用仍符合 schema，但可能重试。提高预算即可恢复。
- **目录抖动** —— 按请求排序可能改变前 K 并重新发布目录消息；影响被一行摘要与基于 digest 的更新路径限制。
- **指标归属错误** —— 实测 <1 % 说明计划必须转向 P2 的会话压缩来实现每请求目标；继续让 P1 承担会把项目优化到错误的体积上。
- **`tool-skill` 中延后的历史读取** —— 目录请求文本会通过已废弃的同步 `Session.eventAt()` 回退到持久日志中最后一条直接用户消息。这是同步读取废弃决定下既有的延后迁移例外，不是新增消费者：该助手同时服务既有的选择路径与新的目录排序，迁移到 Session 投影推迟到用户消息投影出现之后。
